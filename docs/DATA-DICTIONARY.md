# 数据字典

| 字段 | 含义 | 约束 |
|---|---|---|
| `datasets[].id`, `revision` | 数据集和变换修订 | ASCII 字母、数字、下划线和短横，保留前导零；每数据集至多 12 条输入边。 |
| `datasets[].inputs[].dataset`, `lag` | 上游名与读取时差 | 当下游日为 D 时读取 `D−lag`；天数 0–7。依赖图须无环。 |
| `heads[].dataset`, `day`, `version`, `rows` | 当前分区指针及行数 | 分区由 `dataset@YYYY-MM-DD` 标识。当前快照每分区唯一。 |
| `changes[].version`, `previous`, `rows` | 源分区的新版本、预计当前版本、行数 | `previous=null` 代表期望新增。仅源表可登记直接变更。兼容旧 `count` 字段。 |
| `through` | 分区截止日 | 包含该日期，从最早受影响输入向下游传播，不触及截止之后的分区。每条变更回溯最多 31 日。 |

相同变更的重传计为重复。相同分区的候选版本或行数打架时全部隔离，保留行号。每个分区先计算最终应读哪些快照，按数据集拓扑序再按分区日排列。已阻断的计划不会被依赖者误当作有效输入，窗口内未受影响的依赖可复用当前快照。

新版本由下游数据集、规则修订、分区日和排序后的输入版本及行数共同计算 SHA-256。演示数据集执行拼接，各读入分区行数相加。数值使用整数，超出 JSON 常见安全整数范围的汇总或派生数按字符串输出。

写入演练先核验每个待写指针，再一次性生成新视图。回滚先核验仍持有演练发布版本，再逐项恢复原指针，新增分区则移除。任一指针陈旧时整组拒绝。该过程作用于清单中的副本，实际仓库的调度与执行另由值班系统负责。

受影响分区 = 待写 + 复用 + 阻断。输入行数 = 采信 + 隔离 + 重复。写入后的行数 = 原行数 + 待写分区行数增量。阻断保留原快照行数。批次绑定原始字节和规则版本，文件大小至多 300 KiB。

## 交接租约（M8）

| 字段 | 含义 | 约束 |
|---|---|---|
| `leases.lease_id`, `token` | 租约号与 fencing 令牌 | 令牌由库内 `fencing_meta` 单行单调递增，每次获取或交接只增不减。 |
| `leases.status` | 租约状态 | `active` / `handed_over` / `expired`；非活动租约的派发、写入、回滚一律拒绝。 |
| `lease_scope.partition` | 责任范围分区 | 取请求分区所属数据集的无向连通分量闭包；闭包内任一分区已有活动租约即 `SCOPE_CONFLICT`，依赖链不可拆分。互不相连的分量可由不同值班组并行持有。 |
| `handoffs.status` | 交接单状态 | `pending` / `completed` / `rejected` / `expired`。交接单只追加不删除，失败时旧租约保持 `active`，旧范围仍可在单据中追踪。 |
| `replay_requests.idempotency_key` | 请求幂等键 | 库内唯一；同键重试返回既有请求（HTTP 200），不产生第二份。未显式提供时按分区、目标版本与证据哈希派生。 |
| `evidence.evidence_hash` | 放行依据 | 对规范化 JSON 求 SHA-256，内容寻址、只追加，无更新或删除接口；写入前校验证据仍在，缺失抛 `EVIDENCE_NOT_FOUND`。 |
| `write_events.kind` | 落库事件 | `write` / `rollback`，记录当时租约号、令牌、分区、前后版本与证据摘要，形成审计轨迹。 |

派发、写入、回滚都在 `BEGIN IMMEDIATE` 事务内执行，并依次校验：租约仍活动且未到期、提交令牌等于库内当前令牌、分区在该租约责任范围内。令牌不符抛 `STALE_FENCING_TOKEN`，因此交接后旧执行者拿着旧令牌的提交无法落库。到期标记在写事务之外的独立连接先提交，避免随拒绝异常回滚。回滚额外要求当前指针仍是本租约写入的版本，否则抛 `STALE_ROLLBACK`。租约页面（`/console/lease`）只读展示租约、责任范围与等待范围，不提供权限管理与批量运营控件。
